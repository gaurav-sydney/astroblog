## Use cases

| Id | Use case | Path |
| --- | --- | --- |
| UC-1 | A PR into `main` | verify: change-type gates plus the baseline; summary and screenshots as an artifact |
| UC-2 | A push to `main` before go-live | verify only, with a notice that auto-deploy is off |
| UC-3 | First go-live (manual) | dispatch `ref=main`, `rollback_ref=<the current release>` → deploy → verify live |
| UC-4 | Rollback drill (manual) | dispatch with `drill=true` → deploy → the live check fails on purpose → `rollback_ref` is deployed and verified → the job fails, as a drill should |
| UC-5 | A push to `main` after go-live (`AUTO_DEPLOY=true`) | verify → deploy → verify live → on failure, roll back to `github.event.before` |

## Architecture edges

GitHub `main` → Actions `deliver` → the `verify` job (Node 22, Playwright 1.55.0 headless shell) → the `deploy` job (environment `production`, concurrency group `deploy-production`) → the Hostinger API (upload URL, TUS, deploy, cache purge) → automationworker.io → `verify_live.mjs` (headers, live files equal the release, rendered gate) → the rollback edge back to the Hostinger API.

## Tests first (C5, the `pipeline` gate)

1. A change set of `src/content/posts/x.md` plans exactly hygiene, dist, contract, content and rendered: not brand, not chat (AC-M1).
2. `dist/` alone gives the baseline only. `src/styles/` gives brand and rendered. `deploy/` gives the full set except newsletter.
3. The workflow lives at `.github/workflows/deliver.yml`, and `deploy/ci/deliver.yml` no longer exists.
4. The push trigger is `main` only.
5. A push deploys only with `AUTO_DEPLOY == 'true'`. A rollback step exists for push (`github.event.before`) and for dispatch (`rollback_ref`).
6. The dispatch inputs `ref`, `rollback_ref` and `drill` exist.
7. `verify_live.mjs --drill` reports a failure without touching the network.

- The baseline (BL-1 to BL-5) runs in full with `node tests/run.mjs --all` before the M1 PR merges.
