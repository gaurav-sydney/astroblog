# L2, M2: SEO capability and gate

**Parent:** [L1](L1.md), approved 23 Nov 2026. **Depends on:** nothing outside this repo. It goes live with the first deploy after M1's go-live.
**Kind:** feature (D-3): SEO enters as its own capability and gate.

## Components

| Id | Component | Where | What |
| --- | --- | --- | --- |
| C1 | Capability bundle | `capabilities/experience/seo/` | `capability.yaml`, the feature spec, a README, and the `seo` gate test (like `site-assistant`, the bundle holds its own test) |

## Use cases

| Id | Use case | Result |
| --- | --- | --- |
| UC-1 | A crawler reads `/robots.txt` and the sitemap | Every page that matters is listed, and nothing else |
| UC-2 | A feed reader subscribes | `/rss.xml` lists exactly the published posts |
| UC-3 | A link is shared on LinkedIn or X | A large card with the title, description and brand image |
| UC-4 | A search engine reads a post | Valid `BlogPosting` JSON-LD with the author and publisher |
| UC-5 | A new post is added | The build regenerates the sitemap, RSS and JSON-LD. The `dist` gate refuses an un-rebuilt `dist/`. |

## Fit and gap

| AC-M2 need | Fit | Decision |
| --- | --- | --- |
| "sitemap.xml" | `@astrojs/sitemap` writes `sitemap-index.xml` and `sitemap-0.xml`, not one `sitemap.xml` | Use the integration, as the L1 asks. `.htaccess` 301-redirects `/sitemap.xml` to `/sitemap-index.xml` for crawlers that guess the name. The gate checks the index and its page. |
| "lists exactly the non-draft set" | The integration lists every built page | The gate checks that the post URLs in the sitemap equal the non-draft posts, and that only `/`, `/about/` and the posts are present |
| "og:image on every post page" | None today | C7, plus the gate checks that each image file exists in `dist/` |
| "adding a post regenerates them" | Generated at build from the collection | The gate test builds a copy of the site with one extra post, and checks that it appears in the sitemap, the RSS and its own JSON-LD |
| "the seo gate fails if any is missing" | | Negative proof: strip a tag, run the gate, see it fail (recorded below) |

**Routing (a tension in the L1, raised for Gaurav).** AC-M1 says a content-only change runs only the baseline, content and rendered gates. So `seo` does not run on a new post. That is safe by construction: SEO output is generated from the collection, and the `dist` gate refuses a stale `dist/`. AC-M2's "add a post" proof lives in the `seo` gate's own fixture test. `seo` runs for the `seo`, `feature` and `pipeline` change types, and on `--all`.

**Recommendation:** add `seo` to the `content` type too. Its `dist/` checks take under a second. That would change AC-M1's gate list, so it is Gaurav's call. Not done.

## Architecture edges

`src/content/posts/*.md` → the collection → post pages (C2 and C3), the RSS (C5) and the sitemap (C4) → `dist/` → the `seo` gate. On live, the same files are served, and `verify_live.mjs` compares the `.xml` and `.txt` files too.

## Tests first (the `seo` gate)

1. `dist/robots.txt` allows crawling and names `https://automationworker.io/sitemap-index.xml`.
2. The sitemap index points at `sitemap-0.xml`. Its URLs are exactly `/`, `/about/` and one per non-draft post, all absolute on `https://automationworker.io/`.
3. `dist/rss.xml` is RSS 2.0, and its item links are exactly the non-draft posts, newest first.
4. Every post page has:
   - one `BlogPosting` JSON-LD whose headline equals the title, whose datePublished equals the date, whose url equals the canonical, and whose author and publisher are set;
   - `og:type` = `article`, plus `og:title`, `og:description`, `og:url` and `og:image` (absolute), and the image file exists in `dist/`;
   - `twitter:card` = `summary_large_image`.
5. Every indexable page has `Organization` JSON-LD, a canonical, and the RSS `alternate` link. `/subscribed/` and `/404` say `noindex`.
6. **AC-M2 fixture:** a copy of the site with one extra non-draft post and one extra draft. Built to a temp folder, the extra post appears in the sitemap and the RSS and has its `BlogPosting`, and the draft is absent.
7. The `seo` change type exists. A change to `capabilities/experience/seo/` plans the `seo` gate.

## Regression impact

- **BL-4:** the `content` gate is unchanged. The `site-content.json` and assistant contracts are unchanged.
- **BL-3:** the share card is a static PNG and has no secrets. Hygiene runs on it.
- **BL-1:** the head gains tags only, and the rendered and chat gates run (`feature` type).
- **BL-5:** `Seo.astro` adds no CSS.
- **BL-2:** the `dist` gate covers the new files.
- **Live check:** `verify_live.mjs` compares `.html`, `.js`, `.mjs`, `.json` and `.hocon`. It adds `.xml` and `.txt`, so a live sitemap, RSS or robots that differs from the release is caught.
